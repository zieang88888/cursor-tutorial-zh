# 08 高效工作流

> 把 Cursor 嵌入真实开发流程：搭项目、写功能、重构、测试、Debug、Code Review——每个环节都有最佳姿势。

## 从零搭建项目

- **操作路径**：`Ctrl+I` → Agent 模式 → "创建一个 XX 项目，技术栈 XX，包含 XX 功能"
- **示例**："用 Vite + React + TypeScript 创建 todo 应用，含增删改查与本地存储"
- **后续**：让 Agent 跑 `npm install` 并启动 dev server 验证
- **避坑**：让 AI 生成依赖清单并人工确认版本，避免装一堆用不上的包

## 新功能开发（Feature）

- **标准流程**：
  1. Chat 里讨论需求与设计（先想清楚）
  2. Composer + Agent 生成实现
  3. 逐个文件 Review Diff
  4. 让 Agent 补测试并跑通
- **小技巧**：把需求写成一两句"验收标准"，Agent 照此自查

## 重构（Refactor）

- **操作路径**：选中模块 → Agent → "把这个模块重构成 XX 结构，保持行为不变"
- **示例**："把 utils 里的重复逻辑抽成公共函数" "把类组件改成函数组件"
- **避坑**：重构前确保有测试覆盖；让 AI"分步进行，每步验证"，别一次大改

## 写测试

- **操作路径**：选中函数/组件 → Ctrl+K 或 Chat → "为这段代码写单元测试，覆盖正常/边界/异常"
- **适用场景**：补测试、修 bug 后加回归测试
- **避坑**：AI 生成的测试可能"只测快乐的路径"，边界与异常要自己点名要求

## Debug 调试

- **操作路径**：粘贴报错 + @相关文件 → 让 AI 定位根因并修复
- **高级姿势**：让 Agent 加日志 → 跑程序 → 把输出贴回来 → 迭代定位
- **避坑**：让 AI"解释根因再动手"，防止它只修表象不修本质

## Code Review

- **操作路径**：`Ctrl+Enter` 提交框里选 AI 生成提交信息；改动较大时让 Agent "review 这段改动，指出问题"
- **适用场景**：提交前自查、Review 他人 PR
- **提示词**："以资深工程师视角 review：正确性、边界、安全、性能、可维护性"
- **避坑**：AI Review 也会漏，安全关键代码（鉴权/支付/数据删除）必须人工再看一遍

## Git 操作辅助

- **提交信息**：让 AI 根据 diff 生成规范 commit message
- **冲突解决**：粘贴冲突内容 → AI 分析两边意图给出合并方案
- **避坑**：AI 建议的合并方案要在本地验证后再提交

## 日常开发节奏建议

```
1. 开工：Agent 搭骨架 → 人工确认
2. 开发：Chat 想方案 → Agent 写实现 → 人工 Review
3. 验证：Agent 跑测试/类型检查 → 红了让它修
4. 收尾：AI 生成提交信息 → 人工确认提交
```

## 一句话原则

> **AI 负责"快"，你负责"对"——所有 AI 产出都要过一遍你的眼睛，尤其是安全和数据相关代码。**
