# 05 Cursor Rules 规则

> 让 AI 遵守你的团队规范：代码风格、文件结构、禁止事项——写一次，处处生效。

## Rules 是什么

- **定位**：给 AI 的"行为准则"，告诉它你的项目该怎么写代码
- **生效范围**：全局（所有项目）与项目级（当前仓库）
- **适用场景**：统一代码风格、强制技术栈、避免常见错误

## 项目级规则（.cursor/rules）

- **操作路径**：项目根目录创建 `.cursor/rules/` 目录 → 新建 `xxx.mdc` 规则文件
- **推荐结构**：
  ```
  .cursor/rules/
  ├── coding-style.mdc      # 代码风格
  ├── architecture.mdc      # 架构约束
  ├── tech-stack.mdc        # 技术栈与依赖
  └── pitfalls.mdc          # 常见坑
  ```
- **避坑**：规则文件是普通 Markdown，AI 会自动读取；规则过多会稀释注意力，控制在 5 个以内

## 全局规则（Global Rules）

- **操作路径**：Settings → Rules → 添加全局规则（对所有项目生效）
- **示例**："所有代码使用 TypeScript" "中文注释" "禁止使用 any"
- **适用场景**：个人习惯、跨项目通用的规范

## 规则写法示例

```markdown
---
description: 前端代码风格规范
globs: src/**/*.{ts,tsx}
---

- 使用 TypeScript 严格模式，禁止 any
- 组件使用函数式写法 + Hooks
- 状态管理统一使用 Zustand
- 所有 API 调用走 /src/api 封装层
- 错误处理：catch 后必须记录日志并给出用户可读提示
```

- **要点**：description 说明用途；globs 限定作用文件；正文用短句列规则

## 让 AI 生成规则

- **操作路径**：Chat 中粘贴项目现有代码风格 → 让它"总结成 .cursor/rules 规则文件"
- **适用场景**：老项目迁移到 Cursor，快速沉淀规范
- **小技巧**：规则里写"如果违反本规则，提醒我"，AI 会在不符合时主动提示

## 规则与 Agent 配合

- Agent 执行任务时自动加载规则 → 生成的代码自动符合规范
- **示例**：项目规则写明"后端代码必须带输入校验"，Agent 写接口时会自动加校验
- **避坑**：规则与任务指令冲突时，AI 通常先遵守规则——把规则当"宪法"，任务指令当"命令"

## 团队共享规则

- **操作路径**：规则文件提交到仓库 → 团队成员 pull 后自动生效
- **适用场景**：团队统一 AI 协作规范
- **小技巧**：配合 git 分支管理规则变更，改动可评审

## 规则失效排查

| 现象 | 原因 | 对策 |
| --- | --- | --- |
| 规则不生效 | 文件没放在 .cursor/rules 或没保存 | 检查路径与文件名 |
| 规则时灵时不灵 | 上下文太长被忽略 | 精简规则数量与篇幅 |
| globs 不匹配 | 路径模式写错 | 用 `src/**/*.ts` 这类明确模式 |

## 一句话原则

> **规则是给 AI 的"入职培训"——花十分钟写好，后面省十小时返工。**
