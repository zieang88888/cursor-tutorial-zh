# 04 Agent 与 Composer

> 从"改一行"到"干一个任务"：让 AI 自动规划、改多个文件、跑命令——这是 Cursor 提效的真正分水岭。

## Composer 是什么

- **操作路径**：`Ctrl+I`（macOS `Cmd+I`）打开 Composer 面板
- **定位**：多文件、多步骤的 AI 任务工作区，可创建多个 Composer 管理不同任务
- **适用场景**：实现一个功能、重构模块、搭项目骨架

## Agent 模式

- **操作路径**：Composer 输入框下方切换 `Agent` 模式（或 Chat 中同样可切）
- **能力**：Agent 可以读项目文件、改多个文件、执行终端命令、跑测试、根据结果自我修正
- **适用场景**："帮我给这个接口加缓存" "把登录逻辑改成 JWT" 这类跨文件任务
- **避坑**：Agent 会执行终端命令，涉及安装依赖/删除文件时先看清它要干什么

## Agent 的思考过程展示

- **操作路径**：任务执行时右侧展示 Agent 的计划与步骤
- **用法**：看到计划跑偏，随时点"停止"并纠正；不要等它做完才发现方向错了
- **小技巧**：任务越明确，Agent 成功率越高——把验收标准写进指令

## 高质量任务指令模板

```
背景：项目使用 React + TypeScript，现有 /src/api 目录。
任务：新增一个 useUsers 的 hook，支持分页拉取用户列表，带 loading/error 状态。
要求：类型完整、错误处理、导出类型定义；完成后运行 tsc 验证。
```

- **要点**：背景 + 任务 + 要求 + 验证方式，四要素齐全

## 一次生成整个功能模块

- **操作路径**：Composer → Agent 模式 → 描述功能 → 让它"创建所需的所有文件"
- **示例**："创建一个 Express 的 REST API 服务，含用户注册/登录/资料接口，用 SQLite 存储"
- **效果**：AI 生成目录结构、多个文件、依赖说明
- **避坑**：生成后逐个文件 Review，尤其关注鉴权、输入校验等安全相关代码

## 让 Agent 跑测试并修复

- **操作路径**：指令结尾加"跑一下测试，红了就修，直到全绿"
- **适用场景**：改完代码后自动验证
- **避坑**：测试时间长的项目会让 Agent 卡住，可限定"只跑相关测试"

## 多任务并行管理

- **操作路径**：`Ctrl+I` 打开多个 Composer Tab，每个 Tab 一个独立任务
- **适用场景**：同时推进不同模块，互不干扰
- **小技巧**：给每个 Composer 起个清晰标题（如"用户模块""支付模块"），方便回查

## 何时不用 Agent

- 任务模糊、你自己都不知道要什么结果时——先 Chat 讨论清楚
- 涉及不可逆操作（删库、改线上配置）——先拆成小步确认
- 有严格规范要求的代码——用 Rules（第 05 章）约束后再说

## 一句话原则

> **Chat 问路，Ctrl+K 改一点，Agent 干一摊——把 Agent 当实习生用：给够背景、说清要求、检查结果。**
