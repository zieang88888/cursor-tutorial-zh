# 02 Tab 补全与行内编辑

> 这是 Cursor 最"日用"的两个能力：一个帮你接着打字，一个帮你改已写好的代码。

## Tab 自动补全（核心杀手锏）

- **操作路径**：正常写代码 → 光标停在某处 → 灰色预测代码出现 → 按 `Tab` 接受
- **能力范围**：单行补全、多行补全、跨函数补全、根据上下文生成下一步逻辑
- **适用场景**：写样板代码、继续未写完的函数、补参数/返回值
- **小技巧**：灰色预览中按 `Tab` 只接受当前块；`Ctrl+→` 逐词接受；不满意继续打字覆盖即可

## 什么决定了 Tab 补全的质量

- **打开的文件**：Cursor 会读取当前文件及最近打开文件作为上下文
- **项目规则**：`.cursor/rules` 中的规则会影响补全风格（见第 05 章）
- **模型**：Settings → Model 中选择的模型决定补全智能度
- **避坑**：补全在超大文件、超长上下文下会变慢或不准，适时拆分文件

## Ctrl+K 行内编辑（Inline Edit）

- **操作路径**：选中代码 → `Ctrl+K` → 输入修改指令 → Enter → 查看 Diff → `Ctrl+Enter` 接受 / `Esc` 取消
- **适用场景**：改函数名、加注释、修 bug、调整逻辑、重构单函数
- **避坑**：改动跨多个文件或涉及整体架构时，别用行内编辑，用 Composer/Agent
- **小技巧**：选中多行再 Ctrl+K，一次改整块逻辑；指令里可 @ 引用其他文件

## 查看与回滚 Diff

- **操作路径**：AI 修改后代码上方出现 Diff 视图 → 逐块查看 → 接受/拒绝
- **适用场景**：确认 AI 改了什么再落地
- **避坑**：习惯性直接接受会引入隐藏改动；重要代码务必先看 Diff

## 多行编辑

- **操作路径**：选中多行代码 → Ctrl+K → 描述想要的改动
- **适用场景**：批量改格式、统一命名、补注释
- **示例指令**："给这三个函数都加上类型注解" / "把 console.log 全部换成 logger.info"

## 代码解释与提问

- **操作路径**：选中代码 → Ctrl+K → 输入"解释这段代码在做什么"
- **适用场景**：接手旧代码、读不熟悉的仓库
- **小技巧**：让 AI 解释完再问"这段有什么可以优化的地方"，相当于免费 Code Review

## 常见翻车场景与对策

| 场景 | 表现 | 对策 |
| --- | --- | --- |
| 补全总是错的 | 预测代码与意图不符 | 检查模型设置、补全提示词，或先写注释再补全 |
| Ctrl+K 没反应 | 快捷键被占用 | 设置中搜索 `Inline Edit` 重设快捷键 |
| Diff 太多看不清 | 大段改动 | 让 AI"只改必要部分，最小化 diff" |
| 中文注释乱码 | 文件编码问题 | 确保文件 UTF-8 编码 |

## 一句话原则

> **小改动用 Ctrl+K，大改动用 Composer/Agent，日常打字交给 Tab。**
